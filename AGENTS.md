# Руководство по работе с репозиторием

## Структура проекта

Репозиторий содержит два независимых приложения: `frontend/` и `backend/`. Вносите изменения в соответствующем приложении и следуйте дополнительным указаниям в его `AGENTS.md`.

## Тестирование и проверка

Добавляйте тесты для новой функциональности и запускайте проверки соответствующего приложения перед отправкой изменений. Пока ни для одного приложения не настроены набор тестов и порог покрытия.

## GitHub Flow и запросы на слияние

Перед началом задачи создавайте отдельную ветку от `master`: `feat/<nazvanie-fichi>` для новых возможностей или `fix/<nazvanie-baga>` для исправлений. Используйте транслит, нижний регистр и дефисы. Не вносите изменения напрямую в `master`.

После завершения задачи откройте Pull Request из рабочей ветки в `master`, если пользователь не указал другую целевую ветку. Перед созданием проверьте целевую ветку, состав всех изменений и выполните проверки соответствующих приложений. Опубликуйте рабочую ветку и создайте PR через доступный интерфейс GitHub. Существующий PR для той же ветки обновляйте вместо создания дубликата.

Заголовок PR должен кратко описывать итоговое изменение обычным языком, без префиксов Conventional Commits. В описании подробно изложите изменение поведения, основные изменения по приложениям и выполненные команды проверки с результатами. Укажите ограничения и неуспешные проверки, изменения конфигурации и переменных окружения, а также связанную задачу при наличии. Для изменений интерфейса приложите скриншоты или запись; если их получить не удалось, укажите это. После создания сообщите ссылку на PR. Вливайте изменения только через одобренный PR после прохождения проверок.

## Безопасность и конфигурация

Не добавляйте секреты из `.env` в репозиторий. Документируйте необходимые переменные окружения с безопасными примерами значений; локальную конфигурацию не включайте в отслеживаемые файлы.

## Коммиты
- Формат: Conventional Commits (feat, fix, refactor, test, docs, chore)
- Заголовок до 72 символов, в повелительном наклонении
- Без эмодзи, без «significantly improved» и прочей воды
- Тело - только если нужно объяснить «почему», а не «что»
- Один логический шаг - один коммит
