# Руководство по работе с репозиторием

## Структура проекта

Репозиторий содержит два независимых приложения: `frontend/` и `backend/`. Вносите изменения в соответствующем приложении и следуйте дополнительным указаниям в его `AGENTS.md`.

## Тестирование и проверка

Добавляйте тесты для новой функциональности и запускайте проверки соответствующего приложения перед отправкой изменений. Пока ни для одного приложения не настроены набор тестов и порог покрытия.

## Коммиты и запросы на слияние

История Git в этой рабочей копии недоступна, поэтому установить принятый в проекте формат коммитов невозможно. Используйте короткие заголовки в повелительном наклонении, например `Add health check endpoint`, и объединяйте в одном коммите только связанные изменения.

В запросе на слияние опишите изменение поведения, укажите затронутое приложение и выполненные команды проверки. Для изменений интерфейса приложите скриншоты или запись. При наличии укажите связанную задачу и отметьте изменения конфигурации или переменных окружения.

## Безопасность и конфигурация

Не добавляйте секреты из `.env` в репозиторий. Документируйте необходимые переменные окружения с безопасными примерами значений; локальную конфигурацию не включайте в отслеживаемые файлы.

## Коммиты
- Формат: Conventional Commits (feat, fix, refactor, test, docs, chore)
- Заголовок до 72 символов, в повелительном наклонении
- Без эмодзи, без «significantly improved» и прочей воды
- Тело - только если нужно объяснить «почему», а не «что»
- Один логический шаг - один коммит
