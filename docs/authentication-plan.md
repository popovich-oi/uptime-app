# Backend-аутентификация с JWT, refresh-сессиями и ORM

## Краткое содержание

Добавить в Go backend регистрацию, вход и обновление access JWT через refresh-токен. Для PostgreSQL использовать ORM **GORM** с официальным PostgreSQL-драйвером `gorm.io/driver/postgres`. Пользователи и refresh-сессии хранятся в PostgreSQL; Docker Compose поднимает только PostgreSQL.

## Основные изменения

- Подключить зависимости: GORM, PostgreSQL-драйвер GORM, JWT-библиотеку и bcrypt.
- Использовать GORM-модели `User` и `RefreshToken` с уникальными ограничениями, индексами и связью пользователя с refresh-сессиями.
- При старте загрузить конфигурацию из окружения, открыть PostgreSQL через GORM, проверить соединение и выполнить идемпотентную миграцию auth-моделей.
- Реализовать `POST /auth/register`, `POST /auth/login` и `POST /auth/refresh`.
- Access-токен: HS256, срок 15 минут, claims `sub`, `username`, `email`, `iat`, `exp`, `jti`.
- Refresh-токен: криптографически случайная opaque-строка, в базе только SHA-256-хэш, срок 30 дней, ротация при каждом refresh-запросе.
- Передавать refresh-токен через HttpOnly cookie; access JWT возвращать в JSON как `access_token`.
- Использовать единый формат ошибок `{ "error": "..." }` с кодами `400`, `401`, `409` и `500`.
- Добавить `docker-compose.yml` только для PostgreSQL, volume, healthcheck и документацию по запуску.

## Зафиксированные предположения

- Обязательные поля: `username`, `email`, `password`.
- Username длиной 3–32 символа; пароль минимум 8 символов; email проходит базовую RFC-проверку.
- Восстановление пароля, logout endpoint, подтверждение email и reuse-detection всей token family не входят в первую версию.
- Backend и frontend не объединяются в общий Compose-сценарий.
- Миграции выполняются через контролируемый startup-механизм GORM.
